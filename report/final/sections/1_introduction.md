Human activity recognition (HAR) infers what a person is doing from the signals of body-worn inertial sensors. A smartphone already carries an accelerometer and a gyroscope, so activity can be monitored without extra hardware, which supports applications such as fall-risk assessment in elderly care, adherence measurement in rehabilitation and activity feedback in the management of chronic disease. Such systems run on battery-limited devices and must work for people whose data were never seen in training, so computational cost and generalisation to new subjects matter as much as accuracy.

The input is a short multichannel time series, one of the few practical problems on which feed-forward, convolutional, recurrent and attention-based networks are all reasonable choices, and each family has been reported to work well [@ronao2016; @murad2017; @dirgova2022]. A survey of deep learning for sensor-based activity recognition found that no single family wins on every dataset [@wang2019]. Published numbers are nevertheless hard to compare. Papers differ in dataset, window length, input representation and tuning effort, and above all in how the data are split. A random split places windows of the same person in both the training and the test set, so the test score partly measures how well the model recognises that person; one recent Transformer result, for example, uses a random split that is not subject-wise [@dirgova2022]. A subject-independent split, in which the test subjects are never seen during training, is the harder and more realistic test.

This project fixes one evaluation protocol and varies only the architecture. On the UCI HAR smartphone dataset [@ucihar2013; @anguita2013], with 30 subjects and 9 inertial channels sampled at 50 Hz, we train an MLP on the 561 engineered features, and a 1D-CNN, a bidirectional LSTM with a GRU ablation and a Transformer encoder on the raw windows. All models share the official subject-independent test split, the same validation subjects, the same training protocol and the same tuning budget of four configurations.

The contributions of this report are:

- a like-for-like comparison of four architecture families on held-out subjects, reported as the mean and standard deviation over three seeds;
- a cost comparison (parameters, training time and CPU latency) measured on one machine, relating accuracy to suitability for on-device use;
- a window-level error analysis that tests whether the remaining errors are shared by all families or specific to some;
- a public repository (https://github.com/MayDev-404/Human-Activity-Recognition) in which every reported number is generated from committed run files.
